# 批量导入「公积金比例」列设计（三险一金列移除）

- 日期：2026-09-04
- 状态：已评审通过（三节设计获用户确认：彻底移除三险一金列 / 比例兼容多写法 / 留空回退工资参数）
- 前置：`docs/superpowers/specs/2026-09-04-city-policy-library-design.md`（城市政策库）
- 关联文件：`tax-calculator.html`、`README.md`

## 1. 背景与目标

批量导入表当前提供「三险一金」金额列（行内有值则优先用手填金额），与"软件应自动算"的定位相悖；而真正的痛点是**公积金比例只能整批共用「工资参数」里选的一个档位**——单算版可按员工择档（5%~12%），批量反而不能按行指定，混合城市批次（如广州 5%、深圳 12%）无法正确处理。

| 决策点 | 结论（用户确认） |
|---|---|
| 「三险一金」导入列 | **彻底移除**（列映射、模板、文档均不再出现；三险一金一律自动算） |
| 「公积金比例」列格式 | 数字百分比（填 5 = 5%），兼容小数 0.05 与文本 "5%" |
| 行内比例留空时 | 回退「工资参数」全局比例（与现有"行内优先、全局兜底"规则一致） |

### 非目标（本期不做）

- 行内比例的城市档位校验（企业实际比例可能介于档位之间，尊重行值；与自定义城市手填逻辑一致）
- 保留"实际扣缴额覆盖"能力（补缴、封顶等特殊场景此前靠三险一金金额列；彻底移除后只能通过基数列逼近，如未来有强需求再以显式"覆盖模式"回归）
- 劳务报酬、多月累计手工模式、政策库数据结构变更

## 2. 列识别与解析

### 2.1 列映射（COL_KEYWORDS / COL_TYPE_LABELS）

- 删除 `socialInsurance` 类型及其关键词配置、标签 `🛡️ 三险一金(个人)`。
- 新增 `fundRate` 类型，标签 `📊 公积金比例`：
  - 精确匹配：`公积金比例 / 公积金缴存比例 / 公积金个人比例 / 住房公积金比例 / 缴存比例 / 公积金档位 / 个人缴存比例`
  - 模糊匹配：`公积金.{0,8}(比例|档)`
  - 排除：含「基数」的表头（不与 `fundBase` 公积金基数列冲突）

### 2.2 比例解析 parseFundRate()

| 输入 | 解析结果 |
|---|---|
| `5` / `12` | 0.05 / 0.12（>1 视为百分数） |
| `0.05` / `0.12` | 0.05 / 0.12（≤1 视为小数） |
| `"5%"` / `"12%"` | 0.05 / 0.12（先剥 `%` 再按数值规则） |
| 空 / 非数字 / 负数 / >100 | `''`（视为未填，回退全局；不中断批次，与金额列 `readAmt` 容错哲学一致） |

- 解析为小数比例存储（`d.fundRate`），供计算链直接使用。
- 「≤1 视为小数」的 `1` 边界：解析为 100%，非真实档位但无实际场景会这样填（真实公积金比例恒在 0~12% 区间），按规则原样接受、不做特判。

## 3. 计算逻辑（runBatchCalc 工资分支）

- **删除** `hasRowSIAmt`（行内三险一金金额）优先分支；`processWithMapping` 停止读取 `socialInsuranceAmt`。
- 三险一金来源链变为：**行内基数（按城市政策 clamp）→ 全局基数 → 按应发工资作基数（勾选时）→ 0 并标注**。
- 公积金比例链：**行内 `d.fundRate` → `salaryParams.fundRate`**，对三种基数来源均生效；行内比例**不随城市切换重置**、不做档位校验。
- `_siDetail`（悬浮明细数据）增加实际使用的 `fundRateUsed` 字段；`_siMissing` 标注语义不变（行内与全局均无基数时按 0 计）。

## 4. 结果透出与文案

- 批量结果表："三险一金(个人)"列 hover 明细显示所用比例（如「公积金 12% ¥1,440」）；表格不加列。
- CSV 导出（工资模式）：在「三险一金(个人)」后新增「公积金比例」列（如 `12%`），便于对账留痕。
- 下载模板（工资模式）改为：
  `姓名,身份证号,月份,应发工资,城市,社保基数,公积金基数,公积金比例,专项附加扣除`
  示例行覆盖三种写法：张三（广州，填 5）、李四（深圳，填 12）、王五（留空回退全局）。
- 文案同步（所有提到「三险一金」导入列处改为「公积金比例」）：批量格式说明（batch-info-salary）、工资参数卡底部提示、批量预览区计算说明、README「批量计算」与「计税规则」两节。

## 5. 测试与验收

`runSelfTests()` 扩展（既有断言全量回归）：

1. `parseFundRate`：`5→0.05`、`0.05→0.05`、`"5%"→0.05`、`""→''`、`120→''`。
2. 行内比例生效：同基数同行城市，行内 12% 与全局 5% 计算出的公积金/三险一金不同。
3. 留空回退：行内比例留空时结果等于全局比例计算结果。
4. 列识别：表头「公积金比例」映射为 `fundRate`，不误配 `fundBase`/`amount`；「三险一金」表头不再产生任何映射。
5. 模板 CSV 含「公积金比例」列且不含「三险一金」列。
