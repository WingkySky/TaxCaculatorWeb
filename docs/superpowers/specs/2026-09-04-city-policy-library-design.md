# 城市社保公积金政策库设计（工资薪金计算迭代）

- 日期：2026-09-04
- 状态：已评审通过（四节设计均获用户确认）
- 前置：`docs/superpowers/specs/2026-09-04-salary-income-tax-design.md`（工资薪金计算首版）
- 关联文件：`tax-calculator.html`、`README.md`

## 1. 背景与目标

首版工资薪金计算用一套全局手工参数（单一基数上下限 + 四项比例）计算三险一金，过于简化：

1. 各城市社保公积金政策不同，**基数上下限分险种各不相同**（如广东养老/失业按全省口径、医疗单独设限），**比例也分城市**；
2. 批量场景下，工资表通常没有基数列，缺少"选城市后整批适用"的能力。

本次迭代引入**城市政策库**并打通批量：

| 决策点 | 结论（用户确认） |
|---|---|
| 批量适用方式 | 全局选城市政策 + 表格行内「城市」列覆盖，两者都要 |
| 城市覆盖 | 内置 10~12 个主要城市 + 自定义 |
| 数据维护 | 内置 + UI 可编辑 + 导入/导出 JSON |
| 年度组织 | 多年度记录（含生效月区间）+ 按月份自动匹配，可手动固定 |
| 数据结构 | 方案 A：城市 → 年度 → 险种 三层嵌套，演进现有 salaryParams |

### 非目标（本期不做）

- 单位部分比例、用工成本测算
- 工伤、生育险种（个人不缴；生育已并入医疗）
- 政策库在线更新（无可靠免费数据源，file:// 有跨域限制）
- 跨城市/跨年度换缴的累计补差计算
- 劳务报酬功能变更

## 2. 城市政策库数据模型

```js
// 险种键：pension 养老 | medical 医疗(含生育) | unemployment 失业 | fund 公积金
// 每个险种：personal 个人比例(小数)；lower/upper 基数下上限（null = 不限）
// 公积金额外：rates 可选比例数组（公司择档 5%~12%）
const CITY_POLICY_LIBRARY = {
  guangzhou: {
    name: '广州',
    years: {
      '2025': {
        label: '2025年度（2025-07 ~ 2026-06）',
        effective: ['2025-07', '2026-06'],
        items: {
          pension:      { personal: 0.08,  lower: ..., upper: ... },
          medical:      { personal: 0.02,  lower: ..., upper: ... },
          unemployment: { personal: 0.005, lower: ..., upper: ... },
          fund:         { personal: 0.05, rates: [0.05,0.06,0.08,0.10,0.12], lower: ..., upper: ... }
        }
      }
    }
  },
  // shenzhen / beijing / shanghai / hangzhou / nanjing / suzhou /
  // chengdu / chongqing / wuhan / xi'an / tianjin ...
};
```

要点：

- **只建模个人缴费的 4 个险种**；同城市内各险种独立维护比例与上下限（分险种口径差异正是本次建模动机）。
- **年度键 = 社保年度起始年**；`effective` 为生效月区间（闭区间，`YYYY-MM`）。匹配规则：工资月份 `m` 满足 `effective[0] ≤ m ≤ effective[1]` 即适用该年度；自然年度城市（如北京）区间为 `['2025-01','2025-12']`。
- **自定义城市**：`custom` 条目，`years.custom.effective = ['2000-01','2999-12']`，四险种比例可填、上下限留空即不限——完全覆盖首版手工模式的行为。
- 内置 12 城：北京、上海、广州、深圳、杭州、南京、苏州、成都、重庆、武汉、西安、天津。
- **数据准确性**：内置数值为参考值；实现阶段按公开资料核对 2024/2025 年度数据，无法核实的字段在数据中标注 `pending: true`；UI 常驻提示"以当地社保部门公布为准"，政策管理弹层可直接修改并导入导出。

## 3. 参数与计算逻辑

### 3.1 salaryParams 演进

```js
salaryParams = {
  cityId: 'guangzhou',   // 城市 key 或 'custom'
  policyYear: 'auto',    // 'auto' 按月匹配 | 固定年度键
  socialBase: 10000,     // 社保缴费基数（元/月）
  fundBase: '',          // 公积金基数；'' = 跟随社保基数
  fundRate: 0.05,        // 从城市 fund.rates 中选择；custom 手填
  extraDeduction: 0      // 专项附加扣除（元/月）
};
```

首版的 `ratePension/rateMedical/rateUnemployment/rateFund/baseLower/baseUpper` 废弃，由城市库（含 custom 条目）取代。

### 3.2 政策解析与计算

- `resolvePolicy(cityId, month)` → `{ cityKey, yearKey, items }`：custom 直接返回；否则取 `effective` 覆盖 `month` 的年度；无匹配时**回退该城市最新年度并在结果中标注**"政策年度未匹配，已用 XX 年度"。
- **逐月匹配**：多月累计与批量均按每条记录的月份解析政策（解决 7 月调整基数的跨年度衔接）；`policyYear` 固定时整批强制使用该年度。
- `computeSocialInsurance(socialBase, fundBase, items, fundRate)` **逐险种计算**：
  - 各险种基数 = `clamp(socialBase, lower_i, upper_i)`（socialBase 缺失/0 → 该险种为 0）；
  - 公积金基数 = `clamp(fundBase || socialBase, fund.lower, fund.upper)`；
  - 返回明细 `{ pension, medical, unemployment, fund, total }`，total 用于计税与实发，明细用于展示。
- 批量三险一金兜底链（与首版一致，clamp 换为城市政策）：行内三险一金金额 > 行内基数（按该行城市政策 clamp）> 全局基数（按全局城市政策 clamp）> 0 并标注。
- **新增批量开关「无基数列时按应发工资作基数」**（默认关）：开启后，无行内基数且全局基数未设置时，以当月应发工资为基数按城市上下限 clamp 计算。

### 3.3 同月多笔与跨年（沿用首版规则）

同月多笔合并计税、三险一金/减除费用同月只计一次（从当月首笔扣减）；跨年重置；不适用断月重置与旧政策。

## 4. UI 交互

### 4.1 工资参数卡（改造）

- 行 1：城市下拉（内置 12 城 + 自定义）、年度下拉（该城市年度列表 + 「自动匹配」默认）、公积金比例下拉（城市 `rates` 择档；custom 为数字输入）、社保基数、公积金基数、专项附加扣除。切换城市时，公积金比例保持当前值若仍在该城市 `rates` 内，否则重置为最低档。
- 行 2：只读明细表「险种 | 个人比例 | 基数下限 | 基数上限 | 按当前基数实缴」，随城市/年度/基数联动。
- 「⚙ 政策数据管理」按钮 → 管理弹层。

### 4.2 政策管理弹层

- 左侧城市列表（可新增/删除城市，内置城市不可删、可改数据）；右侧年度下拉（可新增/删除年度）+ 险种编辑表格（比例%、下限、上限、公积金比例区间列表）。
- 「📥 导出 JSON」导出整个库；「📤 导入 JSON」覆盖前弹确认。
- 顶部常驻提示：内置数据为参考值（标注数据截止日期），以当地社保部门公布为准。
- 修改即时生效（内存），不写 localStorage（纯单文件工具，行为与现有工具一致）。

### 4.3 批量页

- 「选择计算方式」区新增：整批城市下拉（默认「跟随工资参数」）+ 「无基数列时按应发工资作基数」开关。
- 城市适用优先级链：**行内城市列 > 整批城市选择（非「跟随」时）> 工资参数卡城市**；基数同样按最终生效城市的政策 clamp。
- 新增列类型 `city`：关键词 `城市|参保地|缴纳地|工作城市|参保城市|社保城市`。
- 城市名匹配：精确名 + 别名容错（"广州市"→广州、多余空白裁剪）；未识别城市名 → 回退全局城市并标注"未知城市"。
- 批量页格式说明文案同步增加城市列与开关说明。

## 5. 结果展示、测试与验收

### 5.1 结果展示

- 批量结果表与 CSV 新增列：**城市、政策年度**；三险一金列 hover 提示分险种明细。
- 多月累计明细表三险一金列同上；备注列显示适用政策（城市·年度）。
- 年度未匹配 / 未知城市的标注沿用现有黄色提示行样式。

### 5.2 测试（runSelfTests 扩展）

1. 广州 vs 深圳同月薪（如 8000）：不同上下限产生不同实缴三险一金。
2. 年度自动匹配：2025-06 与 2025-07 落入不同年度记录（以广州 7 月年度切换为例）。
3. 固定年度覆盖 auto。
4. 行内城市列覆盖全局城市；未知城市回退并标注。
5. 「按应发工资作基数」开关生效（clamp 到城市上下限）。
6. 政策库导出→导入 roundtrip 一致。
7. 既有 17 项断言回归（工资正向/反算/clamp/劳务）。

### 5.3 验收算例

以广州 2025 年度与深圳 2025 年度、月薪 8000、无公积金基数差、公积金 5% 档对比：两者因医疗/公积金上下限与比例差异产生不同三险一金与实发；具体数值在实现时以内置核对数据为准写入测试断言。

## 6. 风险与缓解

| 风险 | 缓解 |
|---|---|
| 内置政策数据过期或失准 | 参考值标注 + UI 免责提示 + 管理弹层可改 + 导入导出 |
| 城市别名匹配遗漏 | 别名表集中维护；未识别回退全局并标注，不静默算错 |
| 逐月匹配性能（大批量） | 政策解析按 (城市,月) 记忆化缓存 |
| 首版参数字段废弃 | custom 城市完全承接旧行为，老用法（手填比例上下限）不受影响 |
