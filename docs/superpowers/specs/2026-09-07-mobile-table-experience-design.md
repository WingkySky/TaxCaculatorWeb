# 手机端表格体验优化设计

- 日期：2026-09-07
- 状态：已与用户对齐（视觉伴侣逐屏确认：范围 4 处全选；主力方向=分层展开方案 C）
- 关联：`2026-09-05-ui-redesign-architecture-design.md`（antd 企业蓝/侧边栏控制台双主题基建）

## 1. 背景与目标

现状：全站宽表格在 ≤768px 视口靠 `overflow-x:auto` 横向滑动兜底。四处痛点（用户已确认全部纳入范围）：

| 位置 | 问题 |
|---|---|
| 多月对比 · 逐月明细（`page-multi.js`） | 工资模式 13 列、`min-width:1340px`，「税后收入」在第 12 列，滑动约 4 屏且滑动时月份不可见 |
| 多月对比 · 年终奖方案对比 | 4 列但「说明」列长文本被挤成细长条，行高暴涨 |
| 批量流水线 4 张表（`batch-view.js`） | 列数随上传文件变化，宽度不可控 |
| 政策库 · 政策编辑表单（`page-policy.js`） | 「险种 × 输入框」6 列表单，12px 小字挤压难读难改 |

目标：
1. 手机端关键数字零横向滑动，次要细节按需展开；
2. 桌面端（>768px）渲染结果与现状**逐像素一致**；
3. `file://` 双击打开、GitHub Pages 挂网、双主题、打印报告均不受影响。

## 2. 机制与断点

- **不做两个网站、不做 UA 检测**。断点 `768px`（与 `layout.css` 现有汉堡菜单断点一致），纯 CSS 媒体查询实时跟随窗口宽度；手机横屏、拖窄桌面窗口均自动切换。
- 「变形表」（逐月明细、年终奖卡、政策编辑表单）采用**双 DOM** 策略：渲染函数同时输出桌面形态与移动形态，CSS 类 `.only-desktop` / `.only-mobile` 二选一显示。行数少（≤13），体积代价可忽略；不监听 resize；导出 CSV/Excel、打印报告读取数据层与桌面 DOM，不受影响。
- 「宽表」（批量页，列数不可控）**不做双 DOM**，只做纯 CSS 滑动增强（吸附首列 + 淡出提示）。
- iPad 竖屏宽度恰为 768px，将落入移动形态——与现有侧边栏行为一致，接受。

## 3. 分项设计

### 3.1 多月对比 · 逐月明细（方案 C：分层展开）

- **摘要**：复用现有 `.summary-grid`（≤640px 已自动两列），不新增摘要条。
- **紧凑表 5 列**：月份 / 税前（`inLabel`）/ 税率 / 本期预扣 / 税后（`outLabel`）。列头沿用 `incomeIOLabels` 的方向文案，反算方向同样适配。
- **行点击展开**：其余列转为 label:value 网格（备注、三险一金(个人)、单位社保公积金、专项附加、累计发放金额、累计减除费用、累计应纳税所得额、政策类型；非工资模式按实际列集分支渲染，与现表头逻辑同源）。支持多行同时展开/收起；展开态仅是 DOM class，不入 `TaxState`。
- **合计行**：紧凑表底部保留「合计」行（月份列显示"合计"）。
- **交互实现**：`ui.js` 新增 `toggleMobileDetailRow(btn)`，行内 `onclick` 调用，与现有代码风格一致。
- **双 DOM**：桌面 `detail-table` 原样包 `.only-desktop`；移动形态包 `.only-mobile`。

### 3.2 多月对比 · 年终奖方案对比（方案 B：行转卡片）

- 移动形态：表格 → 两张方案卡。卡头=方案名；正文=年终奖应纳个税、全年个税合计；「说明」列整段下沉为卡片注脚；「切换到此方案」按钮保留（沿用 `PageMulti.setMultiBonusStrategy`）。当前选择卡带高亮边框与徽标。
- `reverseOnly`（反算方向）分支维持现有文字卡不变。
- 双 DOM（仅 2 行数据）。

### 3.3 批量流水线 4 张表（方案 A：优化滑动，纯 CSS）

- 内联 `style="overflow-x:auto"` 容器统一替换为 `class="scroll-x"`（`base.css` 已有该类）。
- `ui.js` 新增 `enhanceScrollX()`：检测容器 `scrollWidth > clientWidth` 时加 `.is-scrollable`（启用吸附首列 + 右缘淡出），滚到最右时加 `.at-end`（隐藏淡出）。各渲染入口调用一次，并挂 resize 重算。
- 吸附首列：`.is-scrollable` 下 `th:first-child / td:first-child` `position:sticky; left:0` + 实底背景 + 右分隔线；斑马纹/行悬浮背景需同步实底，避免透字。

### 3.4 政策库 · 政策编辑表单（偏方案 B：险种字段卡）

> 勘误：浏览器 mockup 曾画成「城市一览卡」，与实际页面不符。该表实为**编辑表单**（险种行 × 个人比例/单位比例/基数下限/基数上限/公积金比例档输入列），城市/年度由页面上方选择器控制。实际设计如下。

- 移动形态：每个险种一张字段卡。卡头=险种名（+「待核对」角标）；卡体=四个数字输入竖排（label + input）；公积金行追加「公积金比例档」文本输入；`⟲ 恢复官方值` 按钮、占位符、`onchange` 处理器全部保留。
- 桌面端表单原样包 `.only-desktop`；双 DOM（≤6 行）。

## 4. 通用基建

- 新增 `css/mobile-tables.css`（`index.html` 在 `layout.css` 之后引入）：`.only-desktop` / `.only-mobile`、紧凑表、展开明细网格、`.is-scrollable` 吸附与淡出、政策字段卡样式。
- 断点一律字面量 `768px`（CSS 自定义属性不能用于媒体查询）。
- 遵循现有解耦约定：样式进独立文件、行为进 `ui.js`、页面模板改动留在各自 page 文件。

## 5. 边界与错误处理

- 非工资模式（劳务报酬等）列集不同：紧凑列与明细网格按 `isSalary` 分支，与现有表头三元逻辑同源。
- 无计算结果时不渲染任何表格（现状已如此，不新增空态）。
- 分享链接收件端走同一渲染函数，移动端自动获得新形态。
- 批量大行数：无 DOM 复制，`enhanceScrollX` 每容器 O(1)。
- 打印：`print-report.js` 不动；`print.css` 追加两条归口规则（隐藏 `.only-mobile`、恢复 `.only-desktop` 显示），确保打印永远输出桌面表格。

## 6. 验证

- **回归门**：`node tests/run.js`（加载子集含 `page-multi.js`、`batch-view.js`）。自测补充：双 DOM 结构存在性、紧凑表列数、方向文案分支；全绿为过。
- **手工冒烟**：临时 http 服务器（`file://` 受限）+ devtools 375px 视口，逐页核对移动/桌面双态；冒烟前重置 UI 状态；`file://` 双击抽查。
- **桌面回归**：>768px 视口逐页比对改动前截图，确认逐像素一致。

## 8. 非目标

- 桌面端任何视觉改动；
- 汇算清缴页窄表（2~3 列）改造（现状可读）；
- 引入表格库 / 触屏手势库；
- 平板专属布局（768~1024px 维持桌面形态）。
