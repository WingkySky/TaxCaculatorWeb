# 年度汇算清缴设计（工资薪金 + 劳务报酬为主，稿酬/特许权手工兼容）

日期：2026-09-07
状态：已与用户确认（范围：两类为主+两项手工；预扣来源：估算+可手填覆盖）

## 背景与目标

现有工具覆盖月度预扣口径（工资累计预扣、劳务按次/累计）。年度汇算是综合所得的年度终点：全年收入额合并、减除年度扣除后按年度税率表计税，与已预扣税额比较得出**应退/应补**。本特性新增「年度汇算」页，双人群兼顾：零基础用户全估算即可用，专业用户可手填个税 APP 的真实预扣值精算。

政策口径（2019 起现行综合所得制度）：

- 收入额折算（年度汇算口径）：工资全额；劳务报酬 ×80%；稿酬 ×80%×70%；特许权使用费 ×80%。
- 应纳税所得额 = 收入额合计 − 60,000（基本减除）− 专项附加扣除（年度口径）。
- 年度税率表与现有 `TaxEngine.BRACKETS` 同一张（3%~45%，级距 36,000/144,000/300,000/420,000/660,000/960,000），**直接复用，不建第二张表**。
- 预扣估算口径：工资与劳务**均复用现有累计预扣引擎**（本工具劳务为「平台连续劳务」，2025-10 起累计预扣法，与多月累计页口径一致——不引入经典「劳务报酬按次 20/30/40 预扣表」，避免双口径混淆）；稿酬 = ×80%×70%×20%；特许权 = ×80%×20%。
- 免汇算提示：补税 ≤400 元或综合所得年收入 ≤12 万（依法预扣预缴前提下）可免于办理。

## 已确认的决策

1. **收入范围**：工资薪金 + 劳务报酬为完整输入（预扣可直接衔接现有引擎）；稿酬/特许权以年度总额手工输入兼容。
2. **预扣来源**：工具估算 + 可手填覆盖（覆盖后标注「手填」）。

## 方案

### 1. 入口与页面结构

- 侧栏「计算」组新增第三项**「年度汇算」**（`#/annual`），路由/显隐复用现有机制；顶栏劳务/工资切换对本页无效果（全年口径）。
- 页面自上而下：**年度选择**（默认当前年）→ **收入区** → **扣除区** → **计算按钮** → **结果卡**。

### 2. 收入区

- **工资薪金**：12 个月网格（与多月页同交互），三险一金（个人）月值与专项附加月值取自「工资参数」卡（只读引用并显示来源）。
- **劳务报酬**：12 个月网格（同交互）；预扣估算复用现有累计预扣引擎（含 2025-10 新旧政策切换与断月重置开关，与多月累计页口径一致）。
- **带入**：「带入多月累计页当前结果」按钮——当次会话算过则一键填入对应类型的月份与金额；带入是单向的，汇算页编辑不回写多月页。
- **稿酬 / 特许权使用费**：各一个年度总额输入框（可留空）。
- 每类收入的「已预扣税额」输入框：留空 → 用估算值；填写 → 用实际值并在结果中标注「手填」。

### 3. 扣除区

- 基本减除费用 60,000 固定展示；
- **专项附加 7 项按年度口径独立输入**（与月度分项面板解耦、互不写状态），预填国家标准：子女教育 24,000/孩、3 岁以下婴幼儿照护 24,000/孩、继续教育（学历 4,800 或职业资格 3,600 二选一）、住房贷款利息 12,000、住房租金 18,000/13,200/9,600 三档（按城市，与房贷互斥）、赡养老人 36,000（独生）或非独生分摊每人 ≤18,000、大病医疗按「自付超 15,000 部分」实际数填（≤80,000）。

### 4. 结果卡

- 收入额合计（分类明细：工资全额、劳务/稿酬/特许权折算后）→ 应纳税所得额 → 适用税率/速算扣除数 → **应纳税额**；
- 已预扣税额分类明细（每类标注「估算」或「手填」）；
- **应退税（绿）/ 应补税（橙）**；
- 政策提示行：免汇算条件（补税 ≤400 或年收入 ≤12 万）+「退税需办理年度汇算申报方可退，数值仅供参考，以税务机关汇算为准」。

### 5. 实现与测试

- 新模块 `js/annual-engine.js`（`window.TaxAnnual`，纯函数）：`incomeOf(kind, amount)`（汇算口径收入额折算：salary 全额 / labor ×80% / author ×80%×70% / royalty ×80%）、`estimateWithholdings(inputs)`（工资/劳务按月序列复用 `TaxEngine` 累计预扣求和，稿酬/特许权按法定预扣率 20% 估算）、`settle(inputs)`（年度计税 + 退补判定 + 免汇算标志）；
- 新模块 `js/page-annual.js`（`window.PageAnnual`）：表单渲染、带入多月结果、读参、结果渲染；
- `index.html`：侧栏菜单 + `#page-annual` 区块 + 两个 script（annual-engine 置于 page-rules 前，page-annual 置于 page-rules 后、app 前——以依赖序为准）；
- `tests/run.js` 加载清单追加两个文件；`self-tests.js` 新增「年度汇算」套件（约 10-12 条）：
  - 收入额折算三类口径（labor ×80%、author ×80%×70%、royalty ×80%）；
  - 劳务预扣估算与多月累计页引擎一致（同一输入序列两处求和相等）；
  - `settle` 标准算例（验收锚点）：全年工资 120,000（月 10,000、三险一金 2,250/月、专项附加 1,000/月）+ 劳务 30,000（6 月一笔）→ 收入额 = 120,000 + 24,000 = 144,000；应纳税所得额 = 144,000 − 60,000 − 27,000 − 12,000 = 45,000 → **应纳税额 1,980**；预扣估算 = 工资累计预扣 630 + 劳务累计预扣（6 月单笔：24,000 − 5,000 = 19,000 → 3% → **570**）；**应补 1,980 − 630 − 570 = 780**（劳务并入综合所得后跳档 10%，月度预扣按 3% 缴——预扣不足需补税正是劳务并入的常态）；
  - 手填覆盖生效、免汇算边界（补 400 内）、空输入防呆。

## 边界（不做的）

- 不做其他扣除（年金/商业健康险/捐赠）、不做经营所得、不做境外抵免；不做申报操作指引之外的流程性功能。
- 不改动现有月度计算引擎与多月/批量页（`annual-engine` 只读其结果作为「带入」数据源）。
- 工资三险一金/专项附加在汇算页只读引用「工资参数」卡，不在汇算页二次编辑。

## 实施记录（2026-09-07）

已实施并验收通过：

- 回归门 **154/154**（新增年度汇算套件 18 条：收入额折算三类、劳务旧政策月不扣税、工资/劳务预扣与引擎一致、标准算例、手填覆盖、免汇算边界、空输入防呆），Git Bash 与 PowerShell 双 shell 全绿；file://（Edge 无头）四套件全绿、零 JS 错误。
- 浏览器冒烟（no-store 服务器 + IAB）：菜单/路由、带入多月结果（工资 12 月、三险一金年额自动估算 27,000）、标准算例全链复现（taxable 45,000 → 应纳税额 1,980 → 预扣 630+570 → **应补 780**、10% 档、无免汇算标志）。
- **产品修正（实施中发现）**：专项附加 7 项由「预填国家标准并直接计入」改为「默认 0、placeholder 显示国家标准」——预填全部标准值叠加（约 10 万/年）会把无对应扣除用户的应纳税所得额压成 0，严重失真；国家标准保留为填写提示。
- 实施记录补充：规格算例初版把退补方向写反（劳务并入跳档后预扣不足是**补税**常态，锚点应为应补 780 而非应退），自检断言先行暴露并修正。
- 环境教训（已记入项目记忆）：IAB 会缓存旧版 js 造成冒烟结果假象——排查顺序应为「node 直算核心函数 → headless 冷启动验证初始化 → no-store 服务器做交互冒烟」。
