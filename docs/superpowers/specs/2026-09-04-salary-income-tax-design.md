# 工资薪金个税计算功能设计

- 日期：2026-09-04
- 状态：已评审通过（四节设计均获用户确认）
- 关联文件：`tax-calculator.html`、`README.md`

## 1. 背景与目标

本工具目前只支持平台连续劳务报酬个税计算（多月累计手工输入 + 批量表格计算，含 2025-10 新旧政策切换）。本次增强在**不改变现有劳务功能**的前提下，新增**工资薪金**所得的累计预扣法计算，覆盖两个页签：

- 「多月累计」：手工输入每月应发（或期望实发），双向互算。
- 「批量计算」：上传 CSV/Excel，识别工资相关列，按人按月累计预扣。

### 需求决策记录（用户确认）

| 决策点 | 结论 |
|---|---|
| 计算方向 | 税前→税后 与 税后→税前 双向互算 |
| 三险一金 | 按社保基数 × 比例自动计算，比例可编辑 |
| 页签范围 | 多月累计 + 批量计算 两个页签都支持（完整对齐） |
| 实现方案 | 方案 A：抽象"计税策略"引擎，两页签共用流水线 |

### 非目标（本期不做）

- 年终奖/全年一次性奖金单独计税
- 汇算清缴退税（预扣税额为负时仅取 0）
- 单位部分社保公积金
- 按城市自动匹配社保比例表（由用户手工调整比例兼容）
- 劳务报酬现有行为的任何变更

## 2. 计税引擎（策略抽象）

### 2.1 策略对象

新增 `TAX_STRATEGIES = { labor, salary }`，重构 `calcTaxForward` / `calcTaxReverse` 接收策略参数（缺省 `labor`，现有调用行为不变）。每个策略定义：

| 钩子 | labor（现有） | salary（新增） |
|---|---|---|
| `includedIncome(income)` | 收入 × 80% | 收入 100% |
| `monthlyDeduction(state)` | 5000 | 5000 + 三险一金（当月） + 专项附加（当月） |
| `postTaxOf(preTax, currentTax, state)` | preTax − currentTax | preTax − 三险一金（当月） − currentTax（实发） |
| 适用旧政策（2025-10 前） | 是（不扣税） | 否，始终累计预扣 |
| 断月重置 | 可选开关 | 不适用（UI 隐藏） |
| 跨年重置 | 是 | 是 |

### 2.2 工资薪金公式（累计预扣法）

- 累计应纳税所得额 = max(0, 累计应发 − 5000×月份数 − 累计三险一金 − 累计专项附加)
- 累计应纳税额 = round2(max(0, 累计应纳税所得额 × 税率 − 速算扣除数))
- 本期预扣 = max(0, 累计应纳税额 − 累计已预缴)
- 税率表沿用现有 `BRACKETS`（3%~45% 七级，速算扣除数 0/2520/16920/31920/52920/85920/181920）
- 税后实发 = 应发工资 − 个人三险一金 − 本期预扣

### 2.3 三险一金（专项扣除）

- 个人部分 = 社保基数 × (养老比例 + 医疗比例 + 失业比例) + 公积金基数 × 公积金比例
- 默认比例：养老 8%、医疗 2%、失业 0.5%、公积金 12%（合计 22.5%），全部可编辑；UI 以百分数输入、`salaryParams` 内按小数存储（如 8% → 0.08）
- 公积金基数默认跟随社保基数，可单独修改
- 可选输入社保/公积金基数上下限；填写后基数先 clamp 再计算，留空则不限制
- 三险一金由基数决定、不随应发变化 → 反算函数单调，复用现有二分 + 0.01 精扫逻辑

### 2.4 参数对象 `salaryParams`（全局共用）

```
salaryParams = {
  socialBase: number,        // 社保基数（元/月）
  fundBase: number,          // 公积金基数，空则跟随 socialBase
  ratePension: 0.08, rateMedical: 0.02, rateUnemployment: 0.005, rateFund: 0.12,
  baseLower: '', baseUpper: '',   // 可选，社保/公积金基数上下限
  extraDeduction: number     // 专项附加扣除（元/月）
}
```

## 3. 「多月累计」页签改造

- 页签栏上方新增**「所得类型」切换**（劳务报酬 / 工资薪金，分段按钮样式对齐现有 direction-toggle）。切换后联动：信息框文案、输入提示、参数区显隐、断月开关显隐、批量页签的格式说明。
- 工资模式下，「多月累计」卡片内显示**「工资参数」区**（`salaryParams` 编辑入口）：社保基数、公积金基数、四项比例、基数上下限、专项附加扣除；只读实时显示"每月三险一金合计"。
- 12 月网格与方向切换复用：税前 = 应发工资；税后 = 期望实发。
- 工资模式下隐藏「断月重置」开关（不适用）。
- 结果表新增列：三险一金、专项附加、累计应纳税所得额、税率、本期个税、实发；`exportMultiCSV` 同步增加对应列。

## 4. 「批量计算」页签改造

- 批量跟随页面级所得类型，无需逐文件选择。
- 新增列类型（`COL_KEYWORDS` 扩展 + 确认映射 UI 下拉同步）：
  - **社保基数**、**公积金基数**、**三险一金**（直接金额）、**专项附加扣除**
- 三险一金取值优先级：行内"三险一金"金额列 > 行内基数列 × 全局比例 > 全局 `salaryParams` 基数 × 比例；全部缺失按 0 计并在结果中标注提示。行内公积金基数缺失时跟随行内社保基数（行内社保基数也缺失时才回退全局）。
- 专项附加取值优先级：行内列 > 全局 `salaryParams.extraDeduction`。
- 累计循环复用现有流水线（解析 → 列映射 → 按人分组 → 按月/时间排序）：跨年重置；同月多笔收入合并计税，同月三险一金与减除费用只计一次（基数取该月首笔行内值）；不进入断月重置与旧政策分支。
- 方向切换（税前/税后）复用现有批量方向控件；反算使用行内固定的三险一金与专项附加。
- 结果表与 `exportBatchCSV` 同步增加新列；「表格格式要求」说明文案按所得类型切换。

## 5. 错误处理

- 输入校验：比例限 0–100（%），基数与专项附加为非负数；非法输入拒绝并标红提示。
- 行内基数缺失时的兜底顺序见第 4 节优先级，兜底用全局值仍缺失则记 0 并标注。
- 反算无精确 0.01 解时沿用现有"最小偏差优先、偏差相同取不低于目标"策略。
- 列识别置信度低时仍走现有确认映射 UI，新增 4 种列类型进入可选映射列表。
- 劳务模式回归保障：策略缺省为 `labor`，所有现有调用点不传策略即走原逻辑。

## 6. 测试

文件内新增 `runSelfTests()`（控制台断言，与项目现有习惯一致，不引入测试框架）：

1. 工资正向递进算例（见第 7 节验收算例，逐月核对个税与实发）。
2. 反算往返一致性：正向算出的实发反算回应发，误差 ≤ 0.01。
3. 跨年重置：次年 1 月累计归零。
4. 同月多笔合并：减除费用与三险一金同月只计一次。
5. 基数上下限 clamp 生效。
6. 劳务回归用例：现有正向/反算行为不变（抽样断言）。

## 7. 验收算例

月薪 10,000 元，社保基数 10,000（比例默认 8%+2%+0.5%），公积金基数 10,000 × 12%，专项附加 1,000/月：

- 每月三险一金 = 10,000 × 22.5% = 2,250
- 1 月：累计应纳税所得额 = 10,000 − 5,000 − 2,250 − 1,000 = 1,750 → 税率 3% → 本期个税 **52.50**；实发 = 10,000 − 2,250 − 52.50 = **7,697.50**
- 反算目标实发 7,697.50 → 应发 **10,000**
- 3 月末：累计应纳税所得额 = 30,000 − 15,000 − 6,750 − 3,000 = 5,250 → 累计税 157.50，本期仍 52.50
