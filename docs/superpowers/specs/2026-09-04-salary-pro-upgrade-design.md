# 工资计算专业化升级 · 设计规格（年终奖 / 专项附加分项 / 单位社保 / 公式导出）

日期：2026-09-04
状态：已实现（`tax-calculator.html` + `tax-policy-data.js`），自检 94/94 通过

## 背景与目标

在既有工资薪金累计预扣引擎（见 `2026-09-04-salary-income-tax-design.md`）之上做「专业化」升级，按用户选定范围实现四项能力：

1. **年终奖计税**：单独计税 vs 并入综合所得自动对比择优 + 无效区间避坑提示
2. **专项附加扣除分项**：7 项分项录入 + 政策上限/互斥校验，替代单一「元/月」数字
3. **单位部分社保公积金**：企业用工总成本视角（**本规格推翻原设计文档「非目标」第 3 条**，见文末修订记录）
4. **Excel 公式导出**：导出的 xlsx 中每个派生数字都是真实公式，来源可溯、改输入即重算

不在本次范围：图表、工资条打印、批量身份证校验；劳务报酬「收入≤4000 减 800」注释与代码不符问题另行处理。

## 一、年终奖计税

### 引擎
- `MONTHLY_BRACKETS`：月度税率表（÷12 定档），阈值 3000/12000/25000/35000/55000/80000，速算 0/210/1410/2660/4410/7160/15160
- `getMonthlyBracket(bonus)`：按 **bonus÷12** 比较（实现时曾误用奖金原值比较，已由自检 `年终奖36000→1080` 覆盖）
- `calcBonusTaxSeparate(bonus)`：奖金 × 税率 − 速算扣除数
- `BONUS_TRAP_ZONES`：由月度税率表程序化推导六段无效区间，`from = upTo×12`，上沿 = 税后所得恰好等于下沿税后所得的奖金额 `(netAtEdge − quick)/(1 − rate)`；(36,000, 38,566.67] / (144,000, 160,500] / (300,000, 318,333.33] / (420,000, 447,500] / (660,000, 706,538.46] / (960,000, 1,120,000]
- `calcSalaryCumulativeTax(entries)`：纯函数年度累计税额，供方案对比复用
- `mergeBonusIntoEntries()`：年终奖作为收入插入发放月（当月工资之后；当月无工资时插到月序合适处；当月有工资时不重复加减除费用）
- `compareBonusStrategies(salaryEntries, bonus)`：输出单独计税税额、并入税负增量、两方案全年合计、推荐方式、节税额与无效区间

### 多月累计 UI
- 新增年终奖输入（金额 + 发放月份，默认 12 月），仅工资薪金模式显示
- 结果区「年终奖方案对比卡」：两方案税额对照 + 推荐徽标 + 「跟随推荐 / 单独计税 / 并入综合所得」三个切换按钮（`multiBonusStrategy`，切换即重算）
- 单独计税行独立成行插入发放月（不进入累计链，累计列显示 —）；并入则出现在累计链内
- 反算（税后→税前）方向下并入对比不适用：一律单独计税独立成行，卡片内说明

### 批量
- `COL_KEYWORDS` 新增 `bonus` 类型（年终奖/全年一次性奖金/年度奖金等；排除「工资/月薪/基数/比例/月度/季度/绩效」防止误映射）
- 批量计税流水线重构：`runBatchSalaryPass(group, records, bonusRecs)` 单人计税纯流水线，可重复执行
- `runBatchSalaryPerson()`：有年终奖时按 **人 × 年** 跑两遍（基线 / 全部并入）对比择优；同年多年终奖统一按年择优；反算方向一律单独计税
- 年终奖合成记录不缴社保、不享专项附加；单独行 `makeBatchBonusSeparateRow` 按月序插入

## 二、专项附加扣除分项

- 数据结构 `salaryParams.extraDetail`（`extraDetailDefaults()`），`on: false` 时回退单一总额 `extraDeduction`（向后兼容）
- `computeExtraDetailFor(detail, ym)` 按月计算（职业资格 3600 仅取证月计入），返回 `{ total, messages, medicalAnnual }`；`getExtraDeductionFor(ym)` 统一入口
- 金额标准（2023-01 起）：子女教育 2,000/月/孩；婴幼儿 2,000/月/孩；继续教育学历 400/月、职业资格 3,600 取得当年；房贷 1,000/月；房租 1,500/1,100/800（`suggestHouseRentTier` 按城市推荐，苏州 1,100，用户手选后不再覆盖）；赡养独生 3,000、非独生分摊 ≤1,500 自动封顶；大病医疗仅返回年度金额
- 校验：房贷与房租互斥（UI 勾选自动取消另一项 + 引擎兜底提示）；大病医疗不参与月度预扣，结果区展示年度汇算提示（自付超 1.5 万部分限额 8 万）
- 批量：行内「专项附加扣除」总额列优先级不变（行内总额 > 全局分项按月合计 > 全局单一总额）

## 三、单位部分社保公积金（企业总成本）

- 政策库险种扩为 5 项（新增 `injury` 工伤，个人 0），每险种新增 `employer` 单位比例字段；`fund.employer` 缺省表示单位与个人同档
- `computeSocialInsuranceDetail()` 返回值扩展：`employer: { pension, medical, unemployment, injury, fund, total }` + `socialBaseRaw/fundBaseRaw`（clamp 前原始基数，供公式导出复现）
- 12 城种子按公开口径填写单位比例（广东养老 15%、其余 16%；医疗含生育各城口径不一；工伤统一按行业基准 0.2%），沿用 `pending` 待核对机制，文件头注明参考值属性
- UI：结果表加「单位社保公积金」列（悬停分险种明细）、汇总卡加「企业用工总成本 = 应发 + 单位合计」；参数卡政策预览表加单位比例列与单位实缴/总成本行；批量按人头展示
- 政策弹层编辑表加「单位比例（%）」列；`libraryToRows/rowsToLibrary` 增加「单位比例(%)」列并**按表头嗅探兼容旧格式文件**；`normalizePolicyLibrary()` 在加载/导入/恢复种子时按字段级从种子回退补齐旧存档缺失的 employer/injury，不覆盖用户已改数值，并把险种与字段重排为规范键序（保证 JSON roundtrip 严格相等）
- 百分数→小数用整数换算 `pctToRate = round(n×1e6)/1e8`，避免 `5.2/100 = 0.052000000000000005` 类浮点漂移破坏 roundtrip

## 四、Excel 公式明细导出

- `buildSalaryFormulaGrid(rows, opts)`：多月累计与批量共用的纯网格构建器（可无 XLSX 环境测试）
  - 常量列只有原始输入：应发、社保基数、公积金基数（跟随社保时为 `=F2` 引用）、公积金比例、专项附加
  - 三险一金：`=ROUND(MAX(MIN(基数,上限),下限)×比例,2)`（公积金 `,0` 取整到元），上下限内联可溯源
  - 累计链：每行累计 = 上行累计 + 本期；同月多笔/换人/跨年的基准（chainKey/sameMonth）由生成端判定后写入正确公式；「当月减除费用」为 `=IF(月=上月,0,5000)`
  - 税率/速算：嵌套 IF 七档（年度表与 ÷12 月度表各一套 `fxAnnualRate/fxBonusRate…`）
  - 年终奖单独行：不进累计链，税率按 ÷12 档，税额 `=ROUND(MAX(0,奖金×税率−速算),2)`
  - 「累计已预扣」链用 `=上行已预扣+上行预扣`（而非 `=上行累计应纳税额`），保证减除中途跳增等异常场景与 JS 引擎的 clamp 语义完全一致
- `gridToWorksheet()`：每格同时写公式 `f` 与缓存值 `v`（页面已算好的结果）——Excel/WPS 打开即显示数值，点开可见公式，改输入自动重算
- 导出入口 `exportMultiExcelFormula()` / `exportBatchExcelFormula()`（仅工资薪金模式显示按钮），复用 `ensureXLSX()` 懒加载；CSV 导出保留（增加单位社保与总成本列）

## 自检（runSelfTests 新增 30+ 断言）

年终奖算例（36000→1080、144000→14190、36001→3390.10）；六段无效区间边界；方案对比（月薪 1 万×12 + 36000 → 推荐 separate、节税 1470；插入位置）；单位部分（自定义城市 2970 合计）；专项附加分项（合计/互斥/封顶/取证月/大病医疗）；公式网格抽查（公式串与缓存值成对、÷12 档公式、累计链跨行引用）；「年终奖」列识别；政策库 roundtrip。

## 修订记录：原设计「非目标」的变更

`2026-09-04-salary-income-tax-design.md` 曾将「单位部分社保（企业缴费）」列为非目标（个人到手视角）。本次应用户要求引入单位部分计算与企业用工总成本视角，该非目标自此撤销；政策库数据量相应增加（各城市单位比例 + 工伤），均以参考值 + pending 标记 + 可编辑的方式控制维护成本。
